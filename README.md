# Onegin Task

> Сортировка строк «Онегина» с сохранением исходного порядка во второй части файла.

Программа читает текстовый файл, создаёт массив указателей на строки, сортирует его с помощью `qsort` и записывает результат в `onegin_sorted.txt`. Затем восстанавливает исходный порядок строк и дописывает их в тот же файл.

## Сборка и запуск

Команды для Linux / WSL. Выполняются из корня репозитория:

```bash
g++ -Wall -Wextra -g src/onegin.cpp -o onegin
./onegin data/onegin_orig.txt
```

Путь к входному файлу передаётся первым аргументом: `argv[1]`. Результат сохраняется в текущей папке.

| Часть `onegin_sorted.txt` | Содержимое |
| --- | --- |
| Первая | Строки после сортировки |
| Вторая | Те же строки в исходном порядке |

Между частями нет отдельного заголовка или разделителя. Каждая часть содержит `count_of_strings` строк.

## Как работает программа

**В основе — один буфер с текстом и отдельный массив указателей на строки.**

| Объект | Что хранит |
| --- | --- |
| `buffer` | Все символы прочитанного текста |
| `index` | Адреса начал строк внутри `buffer` |

Сортировка меняет порядок указателей в `index`. Символы строк остаются на своих местах в `buffer`, поэтому по адресам можно восстановить исходную последовательность.

Порядок действий в `main`:

1. `Get_Text_From_File` читает файл в `buffer`.
2. `Strings_Count` подсчитывает строки по символам `\n`.
3. `Strings_Arr` заменяет `\n` на `\0` и заполняет `index` адресами начал строк.
4. `qsort` сортирует указатели, используя `Compare_For_ABC`.
5. `Create_Onegin_File` записывает отсортированные строки, вызывает `Restore_Index` и дописывает исходный текст.
6. `free(buffer)` и `free(index)` освобождают выделенную память.

В примерах ниже используется один и тот же текст:

```text
Zebra
apple
Banana
```

После каждой строки, включая последнюю, стоит `\n`. Примеры на латинице соответствуют побайтовому сравнению в текущем коде.

### 1. `Get_Text_From_File`

Читает содержимое входного файла в выделенный буфер.

```c
char* Get_Text_From_File(int argc, char* argv[], size_t* num_symbols);
```

**Тип:** `char*`

**Принимает:**

| Параметр | Назначение |
| --- | --- |
| `argc` | Количество аргументов командной строки |
| `argv` | Массив аргументов; `argv[1]` содержит путь к файлу |
| `num_symbols` | Адрес переменной, в которую нужно записать размер буфера |

**Возвращает:** указатель на буфер с прочитанным текстом.

**Как работает:**

1. Проверяет `num_symbols` и `argv` через `assert`.
2. Ожидает `argc == 2`: имя программы и путь к файлу. При другом количестве выводит `Input file...`.
3. Открывает `argv[1]` в режиме чтения `"r"` и проверяет результат через `assert`.
4. Вызывает `Get_File_Size` и записывает результат в `*num_symbols`.
5. Выделяет обнулённую память через `calloc`.
6. Читает содержимое файла через `fread`, закрывает файл и возвращает `buffer`.

Дополнительный обнулённый байт после текста служит завершающим символом `\0`. Память буфера освобождается в `main` после записи результата.

> В текущем коде сообщение при `argc != 2` не останавливает выполнение. Для запуска нужен один аргумент — путь к файлу.

### 2. `Get_File_Size`

Определяет, сколько памяти нужно выделить под содержимое файла.

```c
size_t Get_File_Size(char* argv[]);
```

**Тип:** `size_t`

**Принимает:** массив `argv`, где `argv[1]` — путь к файлу.

**Возвращает:** размер файла в байтах плюс один байт для `\0`.

**Как работает:**

1. Проверяет `argv` через `assert`.
2. Создаёт структуру `text` типа `struct stat`.
3. Вызывает `stat(argv[1], &text)` для получения сведений о файле.
4. Возвращает `(size_t)text.st_size + 1`.

**Пример:** для файла размером `19` байт функция возвращает `20`. Это размер выделяемого буфера.

### 3. `Strings_Count`

Подсчитывает строки по символам перевода строки.

```c
int Strings_Count(char* buffer, size_t num_symbols);
```

**Тип:** `int`

**Принимает:**

| Параметр | Назначение |
| --- | --- |
| `buffer` | Буфер с исходным текстом |
| `num_symbols` | Размер буфера |

**Возвращает:** количество символов `\n` в буфере.

**Как работает:**

1. Проверяет `buffer` через `assert` и устанавливает счётчик в `0`.
2. Проходит по буферу от `0` до `num_symbols - 1`.
3. При каждом `\n` увеличивает счётчик на единицу.
4. Возвращает полученное значение.

Для текста `Zebra\napple\nBanana\n` результат равен `3`.

> Для обработки всех строк входной файл должен заканчиваться на `\n`. Последняя строка без него не входит в счётчик и затем не попадает в результат.

### 4. `Strings_Arr`

Разделяет текст на C-строки и создаёт массив указателей на их начала.

```c
char** Strings_Arr(char* buffer, size_t num_symbols, int count_of_strings);
```

**Тип:** `char**`

**Принимает:**

| Параметр | Назначение |
| --- | --- |
| `buffer` | Буфер с текстом, который функция изменяет |
| `num_symbols` | Размер буфера |
| `count_of_strings` | Число переводов строки, найденное `Strings_Count` |

**Возвращает:** массив указателей на начала строк внутри `buffer`.

**Как работает:**

1. Проверяет `buffer` через `assert`.
2. Выделяет память под `count_of_strings + 1` указателей.
3. Сохраняет начало первой строки: `index[0] = buffer`.
4. Проходит по буферу. Каждый найденный `\n` заменяет на `\0` — признак конца C-строки.
5. Сохраняет адрес следующего символа, `&buffer[i + 1]`, как начало следующей строки.
6. Возвращает заполненный массив `index`.

**Пример работы с памятью:**

| Состояние | Содержимое `buffer` |
| --- | --- |
| После чтения файла | `Zebra\napple\nBanana\n\0` |
| После `Strings_Arr` | `Zebra\0apple\0Banana\0\0` |

Здесь `\n` и `\0` обозначают по одному байту. Получается такой массив:

| Элемент | Значение указателя | Строка по этому адресу |
| --- | --- | --- |
| `index[0]` | `buffer + 0` | `"Zebra"` |
| `index[1]` | `buffer + 6` | `"apple"` |
| `index[2]` | `buffer + 12` | `"Banana"` |
| `index[3]` | `buffer + 19` | `""` — пустая строка |

Дополнительный элемент появляется после последнего `\n`. В сортировку и запись идут первые `count_of_strings` элементов; в этом примере — три.

**Связь с буфером:** `index` хранит адреса внутри `buffer`. Они действительны, пока существует этот буфер. Сами строки продолжают занимать исходные участки памяти.

### 5. `Compare_For_ABC`

Определяет взаимный порядок двух строк для `qsort`.

```c
int Compare_For_ABC(const void* left_comp_elem, const void* right_comp_elem);
```

**Тип:** `int`

**Принимает:** адреса двух элементов массива указателей на строки.

| Параметр | Что находится по переданному адресу |
| --- | --- |
| `left_comp_elem` | Указатель на первую сравниваемую строку |
| `right_comp_elem` | Указатель на вторую сравниваемую строку |

**Возвращает:**

| Результат | Порядок строк |
| --- | --- |
| `-1` | Первая строка должна располагаться раньше второй |
| `0` | Строки равны по правилам этого сравнения |
| `1` | Первая строка должна располагаться позже второй |

**Как из аргумента получить строку:**

Каждый элемент `index` имеет тип `char*`. `qsort` передаёт компаратору адрес такого элемента:

| Выражение | Что означает |
| --- | --- |
| `index[i]` | Адрес начала строки |
| `&index[i]` | Адрес элемента массива, в котором хранится этот указатель |
| `left_comp_elem` | Переданный адрес элемента в универсальном виде `const void*` |

Чтобы прочитать указатель из элемента массива, код приводит тип и выполняет разыменование:

```c
const char* s1 = *(char* const*)left_comp_elem;
const char* s2 = *(char* const*)right_comp_elem;
```

Приведение к `char* const*` позволяет прочитать хранящийся по адресу указатель. Внешняя `*` извлекает его значение. После этого `s1` и `s2` указывают на символы строк.

**Как сравниваются строки:**

1. Проверяются оба аргумента через `assert`, затем извлекаются `s1` и `s2`.
2. В начале каждой строки пропускаются символы, для которых `isalpha` возвращает `0`. Пустая строка останавливает этот поиск.
3. Текущие символы приводятся к нижнему регистру через `tolower` и записываются в `c1` и `c2`.
4. Если `c1 < c2`, возвращается `-1`. Если `c1 > c2`, возвращается `1`.
5. Если символы равны и оба являются `\0`, возвращается `0`.
6. Иначе оба указателя сдвигаются на один символ, и сравнение повторяется с шага 3.

**Примеры:**

| Первая строка | Вторая строка | Результат | Почему |
| --- | --- | --- | --- |
| `"apple"` | `"Banana"` | `-1` | После приведения регистра `a` идёт раньше `b` |
| `"APPLE"` | `"apple"` | `0` | Регистр не влияет на результат |
| `"!!apple"` | `"apple"` | `0` | Начальные `!` пропускаются |
| `"app"` | `"apple"` | `-1` | Первая строка заканчивается раньше при совпадающем начале |

**Детали реализации:**

- Пробелы и знаки препинания пропускаются только до первой буквы. Внутри оставшейся части строки они участвуют в сравнении.
- Приведение к `unsigned char` перед `isalpha` и `tolower` обеспечивает корректный диапазон значений для этих функций.
- Обработка идёт побайтно. Текущий компаратор не реализует алфавитную сортировку кириллицы в UTF-8.

### 6. `Create_Onegin_File`

Записывает отсортированный текст и исходную последовательность строк в один файл.

```c
void Create_Onegin_File(char** index, int count_of_strings);
```

**Тип:** `void`

**Принимает:**

| Параметр | Назначение |
| --- | --- |
| `index` | Массив указателей после сортировки |
| `count_of_strings` | Количество записываемых строк в каждой части файла |

**Возвращает:** ничего.

**Как работает:**

1. Проверяет `index` через `assert`.
2. Открывает `onegin_sorted.txt` в режиме `"w"`: создаёт файл или очищает прежнее содержимое.
3. Если открыть файл не удалось, выводит `File cant be created` и завершает функцию.
4. Записывает первые `count_of_strings` строк через `fputs`, добавляя после каждой `\n`.
5. Вызывает `Restore_Index`, который возвращает указатели в исходный порядок.
6. Записывает строки повторно, теперь в исходной последовательности.
7. Закрывает файл и выводит `File was created`.

Для общего примера содержимое выходного файла будет таким:

```text
apple
Banana
Zebra
Zebra
apple
Banana
```

После успешной записи указатели в `index` расположены в исходном порядке.

### 7. `Restore_Index`

Восстанавливает исходную последовательность строк по их адресам в буфере.

```c
void Restore_Index(char** index, int count_of_strings);
```

**Тип:** `void`

**Принимает:**

| Параметр | Назначение |
| --- | --- |
| `index` | Массив указателей, порядок которых нужно восстановить |
| `count_of_strings` | Количество восстанавливаемых элементов |

**Возвращает:** ничего; изменяет порядок указателей в `index`.

**Почему работают адреса:**

Все строки находятся внутри одного массива `buffer`. Строка, которая была раньше в исходном тексте, начинается по меньшему адресу. После сортировки по алфавиту эти адреса сохраняются в элементах `index`.

Поэтому сортировка указателей по возрастанию адресов возвращает исходный порядок строк.

**Как работает пузырьковая сортировка:**

1. Проверяются `index` и неотрицательность `count_of_strings`.
2. Начинается очередной проход `nPass`; признак `swapped` устанавливается в `0`.
3. Внутренний цикл сравнивает соседние указатели: `index[num_elem]` и `index[num_elem + 1]`.
4. Если левый адрес больше правого, `ValueChange` меняет указатели местами, а `swapped` становится равен `1`.
5. За проход наибольший адрес из проверяемой части перемещается в её конец. В следующем проходе эта позиция уже не проверяется: граница равна `count_of_strings - nPass`.
6. Если за весь проход не было обменов, массив уже упорядочен — срабатывает `break`.

**Пример проходов:**

В таблице показаны смещения относительно начала `buffer`. Смещения `0`, `6`, `12` соответствуют строкам `"Zebra"`, `"apple"`, `"Banana"`.

| Этап | Смещения в порядке элементов `index` | Порядок строк |
| --- | --- | --- |
| После `qsort` | `6, 12, 0` | apple, Banana, Zebra |
| После первого прохода | `6, 0, 12` | apple, Zebra, Banana |
| После второго прохода | `0, 6, 12` | Zebra, apple, Banana |

Сравнение адресов здесь опирается на то, что все указатели ведут в один общий буфер.

### 8. `ValueChange`

Меняет местами значения двух указателей на строки.

```c
void ValueChange(char** value1, char** value2);
```

**Тип:** `void`

**Принимает:** адреса двух указателей на строки — `value1` и `value2`.

**Возвращает:** ничего; изменяет значения указателей по переданным адресам.

**Как работает:**

1. Через `assert` проверяет, что адреса ненулевые и различаются.
2. Сохраняет первый указатель в `midValue`.
3. Записывает второй указатель на место первого.
4. Записывает сохранённое значение на место второго.

```c
char* midValue = *value1;
*value1 = *value2;
*value2 = midValue;
```

В `Restore_Index` передаются адреса элементов массива:

```c
ValueChange(&index[num_elem], &index[num_elem + 1]);
```

Тип `char**` позволяет изменить сами элементы `index`: выражения `*value1` и `*value2` обращаются к хранящимся там указателям типа `char*`.

### 9. `Get_String`

Возвращает указатель на строку по её индексу.

```c
char* Get_String(char** index, int num, int count_of_strings);
```

**Тип:** `char*`

**Принимает:**

| Параметр | Назначение |
| --- | --- |
| `index` | Массив указателей на строки |
| `num` | Индекс нужного элемента, начиная с `0` |
| `count_of_strings` | Количество обрабатываемых строк |

**Возвращает:** указатель `index[num]`.

**Как работает:**

1. Проверяет `index != NULL`.
2. Через `assert` проверяет `num >= 0` и `num <= count_of_strings`.
3. Возвращает значение выбранного элемента массива.

Граница в текущем коде **включительная**: разрешён и `num == count_of_strings`. Это дополнительный элемент, выделенный `Strings_Arr`; при завершающем `\n` он указывает на пустую строку.

`Get_String` объявлена и реализована, но в текущем `main` не вызывается.
